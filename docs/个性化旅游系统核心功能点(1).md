# 个性化旅游系统（纯内存版）设计文档

## 一、系统架构

本系统完全基于手写数据结构，在内存中管理数据，并通过 JSON + 二进制文件实现持久化。

### 三层架构

- **CLI 表示层**
  - 菜单驱动
  - 提供 5 个功能入口：推荐 / 路径 / 搜索 / 日记 / 美食

- **Service 业务层**
  - 实现核心业务逻辑
  - 调用算法，操作内存数据结构

- **DataManager 数据层**
  - 启动时加载 JSON / 二进制文件
  - 退出时写回文件
  - 运行期仅操作内存

---

## 二、核心数据结构

### 1. Graph（邻接表）

- 用途：景点与道路关系建模
- 权重：
  - `dist_walk`
  - `dist_bike`
- 复杂度：
  - addEdge：O(1)
  - 遍历邻居：O(degree)

---

### 2. MinHeap（最小堆）

- 用途：
  - A* 优先队列
  - Huffman 构树
- 操作：
  - push：O(log n)
  - pop：O(log n)
  - top：O(1)

---

### 3. Trie（前缀树）

- 用途：搜索自动补全
- 结构：`vector<pair<char, Node*>>`
- 复杂度：
  - 插入：O(M)
  - 补全：O(M + 结果数)

---

### 4. HashMap（手写哈希表）

- 用途：
  - 数据索引
  - 去重
  - 频率统计
- 方案：链地址法
- 支持自动 rehash（负载因子 > 0.75）

---

### 5. STL 辅助

- `std::multimap`：日记排序
- `std::sort`：结果排序
- `vector / string`：通用容器

---

## 三、核心算法

### 1. 景点推荐（Top-K）

- 复杂度：O(N log K)
- 评分公式：score = 0.4 * rating + 0.4 * heat + 0.2 * tagMatch


---

### 2. 路径规划

#### A* 算法

- 复杂度：O((V+E) log V)
- 支持：
  - 步行 / 骑行权重切换

#### TSP 状态压缩 DP

- 复杂度：O(2^N × N²)
- 限制：N ≤ 12

---

### 3. 搜索模块

- Trie：前缀补全
- KMP：字符串匹配
- HashMap：去重
- sort：排序

---

### 4. 日记系统

#### Huffman 编码

- 编码：O(N log N)
- 解码：O(N)
- 压缩率：40%~55%

#### KMP 搜索

- 解压后匹配

---

### 5. 美食推荐

- Top-K 堆排序：O(N log K)
- KMP 搜索：O(N + M)

---

## 四、模块设计

### 1. 景点推荐模块

流程：
1. 加载数据
2. 计算 score
3. 维护 MinHeap
4. 输出 Top-10

---

### 2. 路径规划模块

流程：
1. 构建图
2. 选择权重
3. A* 搜索
4. 路径回溯

---

### 3. 搜索模块

流程：
1. Trie 自动补全
2. KMP 匹配
3. 去重
4. 排序输出

---

### 4. 日记模块

写入：
1. 统计频率
2. 构建 Huffman 树
3. 编码
4. 写入 bin + json

读取：
1. 加载编码表
2. 解码
3. 搜索

---

### 5. 美食模块

流程：
1. 筛选附近餐厅
2. Top-K 或 KMP 搜索
3. 排序输出

## 六、算法汇总

| 算法 | 场景 | 复杂度 |
|------|------|--------|
| Top-K | 推荐 | O(N log K) |
| A* | 路径 | O((V+E) log V) |
| KMP | 搜索 | O(N+M) |
| Huffman | 压缩 | O(N log N) |
| TSP-DP | 多点路径 | O(2^N × N²) |

---

## 七、优缺点

### 优点

- 无数据库依赖
- 全内存操作，速度快
- JSON 易调试
- 算法完整，展示能力强

### 缺点

- 内存占用较大
- 崩溃可能丢数据
- 不支持并发
- 不适合大规模数据
