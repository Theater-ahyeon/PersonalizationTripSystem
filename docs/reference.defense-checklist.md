### 推荐算法详解

**评分公式（C++）：**
```
score = 0.4 × rating + 0.4 × normalizedHeat(heat) + 0.2 × tagMatch
```
其中 `normalizedHeat = min(1.0, heat / 1000.0)`

**评分公式（前端）：**
```
score = 0.34 × ratingScore + 0.28 × heatScore + 0.38 × matchScore
```
其中 `matchScore` 包含分词、兴趣相似组、LSH 候选集匹配。

**Top-K 最小堆原理：**
1. 维护大小为 K 的最小堆
2. 每个候选项：若 score > 堆顶最小分，则弹堆顶、入新项
3. 最终堆中保留的 K 个即为 Top-K，无需全排序
4. 时间复杂度 O(N log K)，空间复杂度 O(K)

### 路线规划算法详解

**Dijkstra 算法：**
- 数据结构：手写 `MinHeap<PathState, PathCmp>` 优先队列
- 时间复杂度：O((V+E) log V)
- 支持：步行/骑行距离、时间、拥挤度、混合交通四种策略

**A* 算法（OSM 路网）：**
- 启发函数：Haversine 球面距离
- 可采纳性：直线距离 ≤ 实际路径距离（保证最优解）
- 复杂度：O((V+E) log V)

**TSP 状态压缩 DP：**
- 第一步：Dijkstra 计算任意两点间最短距离
- 第二步：位掩码 DP 求解最优访问顺序
- 时间复杂度：O(2^N × N²)，限制 N ≤ 12
- 从起点出发，参观所有目标，返回起点

**室内导航结构：**
```
文昌院大门(1F) → 前厅导览台(1F) → 一层电梯厅(1F)
    ↕ (电梯 8m)
二层电梯厅(2F) → 文物展厅(2F) → 数字展映室(2F)
```

### Huffman 压缩流程（C++）

```
正文 → 统计字符频率 → 构建 Huffman 树 (MinHeap) → 生成变长编码
    → 按位打包 → 写入 .bin 文件
元数据 → 写入 .json (含 codebook、频率表、原始/压缩字节数)
```

典型压缩率：40%–55%（取决于文本重复度）

### KMP 搜索原理

```
预处理：构建 next 数组（前缀函数），O(M)
匹配：扫描文本，利用 next 数组跳过已匹配前缀，O(N)
总复杂度：O(N+M)，无回溯
```

## 九、创新点说明

1. **GeoHash 空间索引**：将设施坐标映射为分层字符串，快速缩小附近检索候选集，避免全量扫描
2. **LSH 兴趣相似检索**：用 SimHash + 波段索引实现高维兴趣特征的高效相似匹配
3. **多策略路线规划**：距离/时间/拥挤度/交通工具四种策略，单一路线引擎适配多种场景
4. **室内导航**：模拟文昌院三层建筑结构，覆盖大门-电梯-楼层-房间的完整室内路径
5. **Huffman 日记压缩**：真实二进制压缩，非估算，40%-55% 压缩率
6. **Stitch 风格前端**：旅行产品级视觉设计，非传统课程作业界面
