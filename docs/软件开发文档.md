# 个性化旅游系统（TripSystem）软件开发文档

> 课程设计：个性化旅游系统的设计与实现
>
> 约束：**核心功能不要使用数据库完成**（算法与核心功能基于“内存数据结构 + JSON 导入/文件持久化”）。
>
> 代码仓库：后端位于 [`backend/`](backend:1)。

---

## 1. 软件开发任务的描述

### 1.1 项目背景

面向“景区/校园”等封闭区域的个性化旅游/导览系统，提供目的地与场所推荐、查询、路线规划、附近设施检索、日记与美食推荐、（可选）AIGC 内容生成等。

### 1.2 建设目标

1. 可演示的 Web 系统（前后端分离），后端提供统一 REST API。
2. 课程核心：**自己设计数据结构并编码实现算法**，包括但不限于：TopK、不完全排序、最短路、多目标路线、近邻设施（网络距离）、模糊查找/倒排索引、无损压缩。
3. 满足数据规模要求（目的地 >=200、节点 >=20、边 >=200、设施 >=50 等），并可通过“一键装载”快速准备演示数据。

### 1.3 当前已交付的可运行范围（本阶段）

- “无数据库”模式启动（`nodb` profile）。
- 正式数据集导入：**JSON Schema 校验 + 语义校验 + 幂等更新**。
- 一键装载：从 classpath 导入、或生成满足数量约束的数据集并导入。
- 图算法接口：对导入目的地的数据运行 Dijkstra（最短距离/最短时间）。

## 2. 功能需求说明和分析

> 下述为课程需求模块；“已实现/未实现”以当前仓库状态为准。

### 2.1 旅游推荐（Top10，不完全排序）

- 需求：按热度/评分/用户兴趣等综合排序；只取 Top10；避免全排序；支持动态变化。
- 算法要求：TopK（小顶堆/选择算法），O(N log K)。
- 现状：TopK 算法类已提供（[`TopK.topK()`](../backend/src/main/java/com/tripsystem/modules/recommend/alg/TopK.java:17)），业务推荐接口待补齐。

### 2.2 查询（名称/类别/关键字 + 排序）

- 需求：按名称/类别/关键词查找；结果按热度/评价排序。
- 算法要求：哈希索引/Trie/n-gram/倒排等；结果用 TopK。
- 现状：待实现。

### 2.3 路线规划

- 单目标：最短距离、最短时间（拥挤度影响速度）、交通工具约束与混合。
- 多目标：途经多点并返回起点（<=12 精确 DP，>12 启发式）。
- 室内导航：多楼层与电梯/楼梯建模。
- 现状：单目标 Dijkstra 已实现并接口可用（[`Dijkstra.shortestPath()`](../backend/src/main/java/com/tripsystem/modules/graph/alg/Dijkstra.java:23)，[`GraphController`](../backend/src/main/java/com/tripsystem/modules/graph/GraphController.java:16)）。其余待实现。

### 2.4 场所查询（附近设施，按道路网络距离排序）

- 需求：从道路图某节点出发，对设施按“网络最短路距离”排序；支持类别过滤。
- 现状：设施数据已能随目的地导入（[`Facility`](../backend/src/main/java/com/tripsystem/modules/dataset/model/Facility.java:11)），查询接口待实现。

### 2.5 日记管理与交流（检索/压缩/AIGC）

- 需求：日记 CRUD、热度（浏览量）、评分；标题精确查找；全文检索；无损压缩存储；AIGC 动画生成。
- 现状：待实现。

### 2.6 美食推荐

- 需求：按热度/评分/距离排序；菜系过滤；Top10 不完全排序；模糊查询。
- 现状：待实现。

### 2.7 数据规模与一键演示

- 需求：目的地 >=200；内部节点 >=20；设施 >=50；边 >=200。
- 现状：已支持单目的地满足 nodes>=20、edges>=200、facilities>=50 的一键生成导入。

## 3. 总体方案设计说明

### 3.1 技术选型

- 后端：Spring Boot（默认 `nodb`）
- 前端：Vue（待实现）
- 地图：高德地图 AMap（待实现）
- 数据：JSON 导入 + 内存数据结构（可序列化回文件；本阶段完成导入与内存落地）

### 3.2 总体结构与模块划分（后端）

- `common`：统一返回体、错误码、全局异常处理
  - [`ApiResponse`](../backend/src/main/java/com/tripsystem/common/api/ApiResponse.java:6)
  - [`GlobalExceptionHandler`](../backend/src/main/java/com/tripsystem/common/exception/GlobalExceptionHandler.java:12)
- `dataset`：数据集 Schema/导入/一键装载/统计
  - [`DatasetImportService`](../backend/src/main/java/com/tripsystem/modules/dataset/service/DatasetImportService.java:28)
  - [`DatasetController`](../backend/src/main/java/com/tripsystem/modules/dataset/web/DatasetController.java:19)
- `graph`：道路图模型 + 最短路算法 + 路径接口
  - [`Graph`](../backend/src/main/java/com/tripsystem/modules/graph/model/Graph.java:8)
  - [`Edge`](../backend/src/main/java/com/tripsystem/modules/graph/model/Edge.java:13)
  - [`Dijkstra`](../backend/src/main/java/com/tripsystem/modules/graph/alg/Dijkstra.java:11)
- `data`：内存存储（按 destinationId 分片）
  - [`InMemoryStore`](../backend/src/main/java/com/tripsystem/modules/data/InMemoryStore.java:14)
- `recommend/search/diary/food/aigc/mapProxy`：规划模块（待实现）

### 3.3 “核心功能不使用数据库”的落实方式

- 所有核心算法输入来自：**数据集 JSON** -> 导入校验 -> 内存结构。
- 导入后按 `destinationId` 分片：`destinationId -> DestinationData(graph, facilities, ...)`。
- 数据库若存在，仅能做“对比实验/非核心扩展”，不影响核心功能验收。

## 4. 数据结构说明和数据字典

### 4.1 核心数据结构（内存）

#### 4.1.1 道路图 Graph（邻接表）

- 文件：[`Graph`](../backend/src/main/java/com/tripsystem/modules/graph/model/Graph.java:8)
- 结构：
  - `nodes: Map<Long, Node>`
  - `adj: Map<Long, List<Edge>>`
- 用途：最短路、附近设施距离计算、多目标路线预处理。

#### 4.1.2 Node

- 文件：[`Node`](../backend/src/main/java/com/tripsystem/modules/graph/model/Node.java:8)
- 字段：
  - `id`：节点编号（唯一）
  - `name`：名称
  - `category`：类别（GATE/BUILDING/POI/ROOM 等）
  - `point`：坐标（GCJ-02）
  - `keywords`：关键字集合（用于检索/推荐）

#### 4.1.3 Edge

- 文件：[`Edge`](../backend/src/main/java/com/tripsystem/modules/graph/model/Edge.java:13)
- 字段：
  - `from/to`：有向边端点
  - `distanceMeters`：距离（最短距离权重）
  - `idealSpeedMps`：理想速度
  - `congestion`：拥挤度 (0,1]
  - `allowed`：允许交通方式集合（WALK/BIKE/SHUTTLE）
- 派生：
  - `travelTimeSeconds()`：`distanceMeters / max(0.0001, congestion*idealSpeedMps)`

#### 4.1.4 DestinationData（目的地分片）

- 文件：[`DestinationData`](../backend/src/main/java/com/tripsystem/modules/dataset/model/DestinationData.java:10)
- 字段：
  - `id/name/category`
  - `graph`：该目的地内部道路图
  - `facilities`：设施列表

#### 4.1.5 Facility（设施）

- 文件：[`Facility`](../backend/src/main/java/com/tripsystem/modules/dataset/model/Facility.java:11)
- 字段：
  - `id/name/category`
  - `nodeId`：所在道路节点（用于网络距离排序）
  - `keywords`：关键字
  - `heat/rating`：热度/评分（用于推荐/排序）

#### 4.1.6 InMemoryStore

- 文件：[`InMemoryStore`](../backend/src/main/java/com/tripsystem/modules/data/InMemoryStore.java:14)
- 数据字典：
  - `destinations: Map<Long, DestinationData>`：按 destinationId 分片存储
  - `destinationDigest: Map<Long, String>`：记录上次导入 digest 用于幂等
  - `legacyGraph`：兼容旧示例接口

### 4.2 数据字典（JSON 数据集字段）

- Schema 文件：[`tripsystem-dataset.schema.json`](../backend/src/main/resources/schema/tripsystem-dataset.schema.json:1)

| 字段                       | 类型     | 用途         | 约束                    |
| -------------------------- | -------- | ------------ | ----------------------- |
| `version`                  | int      | 数据集版本   | >=1                     |
| `destinations[]`           | array    | 目的地列表   | 至少 1 个               |
| `destination.id`           | int      | 目的地编号   | >=1                     |
| `destination.nodes[]`      | array    | 内部节点     | **语义校验要求 >=20**   |
| `destination.edges[]`      | array    | 道路边       | **语义校验要求 >=200**  |
| `destination.facilities[]` | array    | 设施         | **语义校验要求 >=50**   |
| `edge.allowed[]`           | string[] | 允许交通方式 | enum: WALK/BIKE/SHUTTLE |
| `facility.nodeId`          | int      | 绑定节点     | 必须存在                |

## 5. 各模块设计说明（算法思想/特点/关系）

### 5.1 数据集导入模块（dataset）

- 入口：[`DatasetController.importDataset()`](../backend/src/main/java/com/tripsystem/modules/dataset/web/DatasetController.java:34)
- 算法/流程：
  1. JSON Schema 校验（结构合法性）
  2. JSON -> DTO 映射
  3. 语义校验（数量、引用完整性、去重）
  4. 构建内存结构（Graph/Facility 等）
  5. 计算 SHA-256 digest
  6. 幂等写入（digest 未变则不替换）
- 与其它模块关系：
  - `graph`、`facility-nearby`、`recommend` 等算法模块均依赖导入后的内存结构。

### 5.2 最短路模块（graph）

- 算法：Dijkstra
- 文件：[`Dijkstra`](../backend/src/main/java/com/tripsystem/modules/graph/alg/Dijkstra.java:11)
- 特点：通过 `WeightFn` 切换“距离/时间”等权重。
- 关系：
  - 路线规划（单目标/多目标）
  - 附近设施（需要从节点出发计算到设施 nodeId 的最短距离）

### 5.3 TopK 模块（recommend）

- 算法：小顶堆 TopK（避免全排序）
- 文件：[`TopK`](../backend/src/main/java/com/tripsystem/modules/recommend/alg/TopK.java:8)
- 特点：O(N log K)，适合 Top10 推荐/排序需求。

## 6. 应用范例执行结果及测试情况说明

### 6.1 启动与健康检查

- 启动（默认 nodb）：见 [`backend/README.md`](../backend/README.md:8)
- 接口：`GET /api/health`

### 6.2 一键装载并运行最短路（已验证）

以下命令在本机已实际跑通（示例端口 8083）：

1. 生成并导入满足数量约束的数据集：

- `POST http://localhost:8083/api/demo/dataset/load-generated?destinationId=1&nodes=25&edges=220&facilities=60&seed=1`

2. 查看装载统计：

- `GET http://localhost:8083/api/admin/dataset/stats`

3. 运行最短距离：

- `GET http://localhost:8083/api/graph/shortest-distance?destinationId=1&start=1&goal=10`

示例返回（简化）：

```json
{
  "code": 0,
  "message": "OK",
  "data": { "totalWeight": 317.12, "pathNodeIds": [1, 25, 21, 10] }
}
```

### 6.3 校验失败示例

- 若导入 JSON 的 `nodes/edges/facilities` 不满足数量约束，将返回 BAD_REQUEST（40001），来源于 [`DatasetImportService.buildDestinationData()`](../backend/src/main/java/com/tripsystem/modules/dataset/service/DatasetImportService.java:100)。

## 7. 评价和改进意见

### 7.1 现阶段评价

- 优点：
  - 核心约束“无数据库”已落实，且有完整的“导入-校验-落地-算法调用”闭环。
  - 数据规模约束可通过一键生成快速满足，便于验收演示。
- 不足：
  - 路线规划尚未覆盖交通工具混合、多目标、室内导航。
  - 推荐/查询/检索/日记/美食模块尚未完成业务接口闭环。

### 7.2 后续改进方向（建议顺序）

1. 附近设施查询：基于最短路距离的 TopK 排序（网络距离）。
2. 推荐 API：对 POI/Food/Diary 引入评分函数 + TopK。
3. 查询与模糊检索：Trie 或 n-gram 索引 + TopK。
4. 多目标路线：两两最短路预计算 + 位掩码 DP + 启发式。
5. 倒排索引与压缩：序列化到文件，作为验收亮点。

## 8. 用户使用说明

### 8.1 环境与启动

- Windows：
  - 构建：`cd backend && .\mvnw.cmd -DskipTests package`
  - 运行：`cd backend && .\mvnw.cmd spring-boot:run`
- 默认 profile：`nodb`（[`application.properties`](../backend/src/main/resources/application.properties:1)）。

### 8.2 数据装载（推荐方式）

- 一键生成导入：
  - `POST /api/demo/dataset/load-generated?destinationId=1&nodes=25&edges=220&facilities=60&seed=1`
- 从资源文件导入：
  - `POST /api/demo/dataset/load-classpath?name=data/dataset-generated.json`

### 8.3 算法调用

- 最短距离：
  - `GET /api/graph/shortest-distance?destinationId=1&start=1&goal=10`
- 最短时间：
  - `GET /api/graph/shortest-time?destinationId=1&start=1&goal=10`
