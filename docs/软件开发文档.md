# 个性化旅游系统（TripSystem）软件开发文档

## 1. 软件开发任务

本项目是面向景区、校园、园区等封闭区域的个性化旅游系统课程设计。当前实现为纯 C++17 CLI 程序，不使用数据库，不包含 Web 后端。

系统采用“CLI 表示层 → Service 业务层 → DataManager 数据层”的三层结构。程序启动时从 JSON 和二进制文件加载数据到内存，运行期间直接操作手写数据结构，退出时将修改写回文件。

## 2. 功能需求

- 景点推荐：根据评分、热度、偏好标签计算综合分，使用 Top-K 小顶堆返回推荐结果。
- 路径规划：第一版基于景点邻接表道路图；第二版基于离线 OpenStreetMap 样例节点和道路边，使用 A* 搜索输出最优路径。
- 场所搜索：使用 Trie 做前缀补全，使用 KMP 做关键词匹配，使用 HashMap 去重。
- 旅游日记：支持写入、浏览、评分排序和关键词搜索；正文用 Huffman 压缩为 `.bin`。
- 美食推荐：按当前景点筛选附近餐厅，使用 Top-K 返回推荐餐厅。

### 第二版优化说明

- 景点推荐固定权重为评分 0.4、热度 0.4、偏好标签 0.2，使用手写 MinHeap 保持 Top-K。
- 场所搜索保留 Trie + KMP + HashMap，结果按匹配类型、评分、热度和名称排序。
- 美食推荐固定权重为评分 0.5、热度 0.3、菜系匹配 0.2，支持菜系偏好输入。
- 日记模块增加样例日记，浏览时按评分降序展示摘要；缺少 `.bin`、编码表为空、内容为空或解码失败时给出提示。

## 3. 技术方案

- 语言：C++17
- 交互：命令行菜单
- 构建：PowerShell + `g++ -std=c++17`
- 数据：`cpp/data/*.json` + `cpp/data/diaries/*.bin`
- 数据库：无

## 4. 核心数据结构

| 数据结构 | 用途 | 复杂度 |
| --- | --- | --- |
| HashMap | 景点/餐厅索引、搜索去重、Huffman 频率统计 | 平均 O(1) |
| MinHeap | Top-K、路径队列、Huffman 构树 | push/pop O(log n) |
| Trie | 名称前缀补全 | O(M + 结果数) |
| Graph | 景点道路邻接表 | getNeighbors O(degree) |

## 5. 数据文件

- `spots.json`：景点 `id/name/category/rating/heat/tags`
- `roads.json`：道路 `from/to/dist_walk/dist_bike`
- `osm_nodes.json`：OSM 风格节点 `id/name/lat/lon/type`
- `osm_edges.json`：OSM 风格道路边 `from/to/distance/mode/road_name`
- `restaurants.json`：餐厅 `id/name/near_spot_id/cuisine/rating/heat`
- `diaries/{id}.json`：日记标题、评分、热度、创建时间、Huffman 编码表
- `diaries/{id}.bin`：Huffman 压缩后的正文比特流

## 6. 构建与运行

```powershell
powershell -ExecutionPolicy Bypass -File .\cpp\scripts\build.ps1
.\cpp\build\tripsystem.exe .\cpp\data
```

## 7. 验收点

- 仓库无旧后端工程和旧构建产物残留。
- 程序可编译并进入固定 CLI 菜单。
- 数据可从文件加载，退出时可保存热度变化。
- 推荐、路径、搜索、日记、美食五个入口均可演示。
- 核心算法和数据结构在 C++ 代码中手写实现。
