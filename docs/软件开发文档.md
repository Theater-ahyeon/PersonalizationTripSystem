# 个性化旅游系统软件开发文档（纯 C++ 版）

## 1. 文档说明

本文档用于统一纯 C++ 版本的项目目标、架构设计、模块划分、数据结构、算法方案和开发状态。

截至 2026 年 4 月 12 日，仓库中只保留 C++ 版本，Java 代码已经清理完毕。

## 2. 项目背景与目标

### 2.1 项目背景

个性化旅游系统面向景区、校园、园区等封闭区域，提供景点推荐、路径规划、场所搜索、旅游日记和美食推荐等功能。项目重点在于通过手写数据结构和算法完成推荐、搜索、路径和压缩等能力，而不是依赖数据库完成常规增删改查。

### 2.2 建设目标

项目目标如下：

1. 构建一个可以独立运行的 C++ 旅游系统
2. 在系统中完整展示手写数据结构与算法
3. 形成从数据加载、业务处理到结果输出的闭环
4. 满足课程设计答辩对于算法实现、复杂度分析和工程组织的要求

## 3. 总体方案设计

### 3.1 设计原则

- 主链路优先
- 算法优先
- 文件持久化优先
- 模块边界清晰

### 3.2 总体架构

系统采用三层结构：

### 表示层

- C++ CLI 主菜单

### 业务层

- 景点推荐模块
- 路径规划模块
- 场所搜索模块
- 旅游日记模块
- 美食推荐模块

### 数据层

- `DataManager`
- JSON 文件加载与保存
- 日记二进制文件读写
- 内存对象统一管理

### 3.3 运行流程

1. 程序启动
2. `DataManager::load()` 加载景点、道路、餐厅和日记数据
3. 初始化 `Graph`、`Trie`、`HashMap` 等内存结构
4. 显示主菜单
5. 用户执行某个功能模块
6. 模块执行完成后返回主菜单
7. 用户退出系统
8. `DataManager::save()` 将变更写回文件

## 5. 核心数据结构设计

### 5.1 Graph 邻接表图

用途：

- 表示景点、道路和内部节点之间的连接关系
- 支撑最短路径计算

典型操作：

- `ensure_node`
- `add_undirected_edge`
- `shortest_path`

复杂度：

- 建边：`O(1)`
- 遍历邻居：`O(degree)`

### 5.2 MinHeap 最小堆

用途：

- Top-K 推荐
- 最短路径优先队列
- 后续 Huffman 构树

复杂度：

- `push`：`O(log n)`
- `pop`：`O(log n)`
- `top`：`O(1)`

### 5.3 Trie 前缀树

用途：

- 名称自动补全

复杂度：

- 插入：`O(M)`
- 前缀查询：`O(M)`

### 5.4 HashMap 手写哈希表

用途：

- 快速按 ID 查找对象
- 搜索与频率统计
- 去重

设计要点：

- 链地址法
- 支持自动扩容和 rehash

## 6. 核心算法设计

### 6.1 景点推荐

目标：

- 根据评分、热度和标签偏好输出 Top-K 景点

示例公式：

```text
score = 0.45 * rating + 0.35 * heat + 0.20 * tagMatch
```

算法：

- Top-K 堆排序

复杂度：

- `O(N log K)`

### 6.2 路径规划

当前实现：

- 单目标最短路径

算法：

- Dijkstra 风格最短路

场景：

- 最短步行成本
- 最短骑行成本

复杂度：

- `O((V+E) log V)`

### 6.3 场所搜索

算法组合：

- Trie：前缀补全
- KMP：字符串匹配
- 排序：结果按评分排序

### 6.4 美食推荐

算法组合：

- 筛选附近餐厅
- Top-K 排序

### 6.5 旅游日记

当前状态：

- 结构预留
- 尚未完整实现

计划算法：

- Huffman 编码与解码
- KMP 搜索
