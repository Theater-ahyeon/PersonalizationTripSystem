### 评分标准
> b. 最短时间策略：拥挤度为 ≤1 的正数，真实速度=拥挤度×理想速度；每条道路的拥挤度与理想速度**自拟**
> c. 交通工具最短时间策略：校区内可选自行车和步行……景区内可选步行和电瓶车……不同交通工具可选择时，考虑不同拥挤度的情况下时间最短
> 加分项：能够选择采用或提出性能更好的算法，或者和常规不一样的算法

#### 2.1 拥挤度改为随机 + 可配置（前端）

**文件：`web/scripts/route-indoor.js`**

**改动 1：** `edgeCongestion()` 函数（约第 824 行）

当前——完全哈希决定，不可编辑：
```js
function edgeCongestion(edge, travelMode = "walk") {
  const name = `${edge.road_name || ""}${edge.from}-${edge.to}:${travelMode}`;
  const hash = stableFraction(name);
  const base = travelMode === "cart" ? 0.7 : travelMode === "bike" ? 0.66 : 0.62;
  return clamp(base + hash * (0.98 - base), 0.55, 0.98);
}
```

改为——如果用户设置了自定义拥挤度则使用，否则随机生成：
```js
// 全局可配置拥挤度映射：edgeId -> congestionValue
let userCongestionOverride = {};

// 每次页面加载时随机生成新的拥挤度（而不是依赖固定哈希）
function edgeCongestion(edge, travelMode = "walk") {
  const key = `${edge.from}-${edge.to}:${travelMode}`;
  if (userCongestionOverride[key] !== undefined) return userCongestionOverride[key];
  // 首次访问时随机生成并缓存
  if (!edge._congestion) {
    const base = travelMode === "cart" ? 0.7 : travelMode === "bike" ? 0.66 : 0.62;
    edge._congestion = Math.round((base + Math.random() * (0.98 - base)) * 100) / 100;
  }
  return edge._congestion;
}
```

enum TravelMode { WALK, BIKE, CART };

constexpr double SPEED_WALK = 75.0;   // m/min
constexpr double SPEED_BIKE = 180.0;
constexpr double SPEED_CART = 300.0;

bool edgeSupportsMode(const OsmEdge& edge, TravelMode mode) {
    if (mode == CART) return edge.mode == "cart" || edge.mode == "both";
    if (mode == BIKE) return edge.mode == "bike" || edge.mode == "both";
    return true; // walk 总是可以
}

double edgeCongestion(const OsmEdge& edge, TravelMode mode) {
    std::string key = edge.road_name + std::to_string(edge.from)
                      + "-" + std::to_string(edge.to)
                      + std::to_string((int)mode);
    std::hash<std::string> hasher;
    double h = (hasher(key) % 10000) / 10000.0;
    double base = (mode == CART) ? 0.7 : (mode == BIKE) ? 0.66 : 0.62;
    return base + h * (0.98 - base);
}

## T5 — 旅游日记全文检索：增加倒排索引

### 评分标准

### 现状

### 实施步骤

**文件：`web/scripts/diary-aigc.js`** 或 **`web/scripts/core.js`**

```js
function buildDiaryInvertedIndex(diaries) {
  const index = {};
  for (const d of diaries) {
    const text = (d.title + " " + (d.content || "")).toLowerCase();
    const words = extractWords(text);
    for (const w of new Set(words)) {
      if (!index[w]) index[w] = new Set();
      index[w].add(d.id);
    }
  }
  return index;
}

function searchDiariesByIndex(query, index, diaries) {
  const words = extractWords(query.toLowerCase());
  if (words.length === 0) return [];
  let result = null;
  for (const w of words) {
    if (!index[w]) return [];
    if (result === null) result = new Set(index[w]);
    else result = new Set([...result].filter(id => index[w].has(id)));
  }
  return [...result].map(id => diaries.find(d => d.id === id));
}
```

## 关于平面图校准的补充说明

### 为什么要手动拖拽校准
PKU 图书馆的 33 个节点坐标是**凭空估算**的，没有参考平面图布局。唯一的解决办法是**人对图、拖节点**——没有自动化方法可以"猜"出每个阅览室在图片上的正确百分比位置。

### 校准工具
`plan/calibrate_pku_library.html` 是独立的 HTML 文件，不需要任何依赖，直接在浏览器打开即可：
- 左侧/中部显示楼层平面图 + 可拖拽节点
- 右侧/底部生成可直接粘贴到 `core.js` 的坐标代码
- 支持触屏操作

### 如果不想手动操作
`plan/室内导航-PKU图书馆节点校准计划.md` 第 4 节给出了每层每个节点的**建议坐标值**，可以直接替换到 `core.js` 后用浏览器预览效果，然后微调。
