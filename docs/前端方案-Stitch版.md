# 个性化旅游系统前端方案（Stitch 版）

## 1. 方案定位

本方案基于 `stitch_smart_personalized_travel_system.zip` 中的 Stitch 原型重新规划前端。Stitch 原型的核心风格是 **Horizon Bound**：浅色旅行产品、蓝色主操作、橙色强调、绿色状态、玻璃拟态浮层、图片驱动内容卡片。

当前项目是数据结构课程设计，前端不应只做“好看页面”，而要服务于验收演示：把 C++ 中的推荐、路径、查询、日记、美食、数据规模和算法过程清楚展示出来。

因此新前端目标是：

- 以 Stitch 的旅行产品视觉为基础，重做当前 `web/` 演示界面。
- 保留纯静态前端，不引入数据库和后端服务。
- 从 `cpp/data/*.json` 读取同一批数据，保证前端展示和 C++ CLI 数据一致。
- 把课程要求的核心算法转化为可视化流程：Top-K、Dijkstra、A*、TSP-DP、Trie、KMP、Huffman。

## 2. Stitch 原型提炼

### 2.1 视觉系统

- 品牌气质：现代、轻盈、旅行感、探索感。
- 背景：浅灰蓝 `#f9f9ff`，大量留白。
- 主色：高饱和蓝 `#0058bc`，用于导航选中态、主按钮、路径线、地图标记。
- 强调色：橙色 `#fd8b00`，用于评分、热度、推荐亮点、美食按钮。
- 状态色：绿色 `#008733`，用于低拥挤、可达、开放状态。
- 卡片：白色或半透明玻璃面板，圆角 16px，轻阴影。
- 导航：顶部固定磨砂玻璃导航，移动端可转为底部图标导航。
- 图片：景点、日记、美食卡片以大图作为第一视觉。

### 2.2 页面结构

Stitch 提供了四类页面参考：

- `_1 Explore`：首页探索、搜索、分类筛选、推荐卡片。
- `_2 Plan`：地图大画布 + 右侧路线详情面板。
- `_3 Community`：日记生成入口 + 社区日记瀑布流。
- `_4 My Trips`：用户资料、行程、收藏景点、足迹统计。

这些页面可映射为本项目前端的四个主导航：

- 探索：景点推荐、美食推荐、服务设施快捷入口。
- 路线：单点最短路、OSM A*、多点 TSP-DP、地图高亮。
- 日记：旅游日记浏览、搜索、排序、Huffman 压缩展示。
- 我的：用户画像、偏好、收藏、浏览热度、数据概览。

课程验收需要的数据概览和算法说明，不建议单独做成一个突兀的“数据页”，而是放入“我的/数据实验室”二级面板，并在各功能页展示小型算法证明卡。

| --- | --- | --- |

## 4. 页面方案

### 4.1 探索页

探索页对应 Stitch `_1` 首页，但内容改成颐和园场景。

首屏布局：

- 顶部大图 Hero：颐和园/昆明湖/十七孔桥背景。
- 标题：`探索颐和园的个性化路线`
- 搜索框：支持景点名、类别、标签、餐厅、菜系。
- 主按钮：`开始推荐`
- 玻璃面板承载搜索框，延续 Stitch 风格。

分类快捷入口：

- 全部
- 自然
- 建筑
- 文化
- 观景
- 出入口
- 美食
- 服务设施

推荐区域：

- 使用 3 列目的地卡片。
- 卡片展示景点图片、名称、类别、评分、热度、兴趣匹配。
- 底部增加一条“热度/兴趣”彩色细条，呼应 Stitch 的 heat bar。
- 卡片操作：
  - 地图定位
  - 设为终点
  - 加入多点游览

美食推荐区域：

- 使用横向卡片或紧凑网格。
- 显示餐厅名称、菜系、附近景点、评分、热度、距离。
- 支持菜系筛选。

算法展示方式：

- 推荐结果旁显示小型说明：
  - `Top-K 最小堆`
  - `评分 / 热度 / 兴趣加权`
  - `无需完全排序即可得到前 10`

### 4.2 路线页

路线页对应 Stitch `_2`。这是整套前端最重要的答辩页面。

桌面布局：

- 左侧 65%：Leaflet 地图大画布。
- 右侧 35%：路线控制与步骤面板。
- 顶部仍保留磨砂导航。

地图层：

- OSM 节点 marker：
  - 景点节点：蓝色外圈 + 白色中心。
  - 普通道路节点：小灰点。
  - 服务设施：按类型使用图标。
- 路径线：
  - 主路径蓝色粗线。
  - 背景加浅蓝光晕。
  - 支持轻微 pulse 动画。

右侧面板内容：

1. 起终点选择
   - 起点 select
   - 终点 select
   - 交通方式：步行 / 骑行

2. 路线策略
   - 最短距离
   - OSM A*
   - 多点游览

3. 多点游览
   - 可勾选多个目标。
   - 展示访问顺序。
   - 明确标记 `TSP-DP`。

4. 附近设施
   - 卫生间
   - 咖啡/餐饮
   - 游客服务
   - 商店
   - 观景点

5. 路线步骤
   - 使用纵向 timeline。
   - 每段显示：
     - from -> to
     - road_name
     - segment distance
     - cumulative distance

课程展示强化：

- 点击“查看算法过程”展开：
  - 当前算法：Dijkstra / A* / TSP-DP
  - 节点数、边数
  - 路径总距离
  - 时间复杂度
  - 是否可达

移动端布局：

- 地图占满上半屏。
- 路线面板作为底部抽屉。
- 抽屉可展开查看完整步骤。

### 4.3 日记页

日记页对应 Stitch `_3`。

首屏：

- 大图 Hero：旅行日记氛围图。
- 标题：`记录你的颐和园旅程`
- 上传区域：
  - `拖入照片`
  - `输入文字描述`
  - `生成日记草稿`

注意：当前项目未真正接入 AIGC，因此按钮可做演示状态：

- 明确在课程答辩中说明：AIGC 是扩展方向，当前重点为日记管理、检索、排序和 Huffman 压缩。

社区日记：

- 使用 Stitch 瀑布流布局。
- 卡片包含：
  - 日记标题
  - 目的地
  - 内容摘要
  - 评分
  - 热度
  - 标签
  - 压缩率

筛选排序：

- 热度
- 评分
- 兴趣匹配
- 最新

搜索：

- 按标题精确/模糊查询。
- 按正文全文检索。
- 按目的地/标签筛选。

算法展示方式：

- 日记卡片上显示 `Huffman 42%` 之类压缩率 badge。
- 搜索结果区域显示 `KMP 全文检索`。
- 排序切换处显示 `热度 / 评分 / 兴趣多关键字排序`。

## 6. 数据绑定方案

继续读取当前数据文件：

```text
cpp/data/osm_nodes.json
cpp/data/osm_edges.json
cpp/data/spots.json
cpp/data/restaurants.json
cpp/data/facilities.json
cpp/data/users.json
cpp/data/diaries/index.json
```

前端状态结构建议：

```js
state = {
  activeView,
  currentUser,
  mode,
  nodes,
  edges,
  spots,
  restaurants,
  facilities,
  users,
  diaries,
  selectedStart,
  selectedGoal,
  selectedStops,
  selectedRoute,
  savedSpots,
  savedRoutes
}
```

推荐算法：

- 前端可保留演示版 Top-K。
- 权重建议和 C++ 统一：
  - ratingScore = rating / 5
  - heatScore = heat / maxHeat
  - interestScore = tag hit ratio
  - score = 0.4 * ratingScore + 0.35 * heatScore + 0.25 * interestScore

路线算法：

- 单点路径：前端使用 Dijkstra 可视化，C++ CLI 保留 Dijkstra/A*。
- OSM 路径：基于 `osm_edges`。
- 多点游览：前端应改为 TSP-DP，而不是贪心最近点，以便和 C++ 一致。

查询算法：

- 设施查询按图上路径距离排序，不使用直线距离。
- 如果设施本身没有道路节点，则使用附近景点节点 + 最后一段 haversine 作为近似。

日记算法：

- 前端展示 `original_bytes`、`compressed_bytes`、`compressionRate`。
- 搜索用本地字符串匹配演示 KMP 思路。

## 7. 交互流程

### 7.1 答辩演示流程

1. 打开探索页，选择用户偏好，展示 Top-K 推荐。
2. 点击推荐景点的“设为终点”，跳转路线页。
3. 路线页展示地图路径和 Dijkstra/A* 信息。
4. 勾选多个目标，运行 TSP-DP 多点游览。
5. 打开附近设施，展示按路径距离排序。
6. 进入日记页，展示热度/评分/兴趣排序与 Huffman 压缩率。
7. 进入我的页/数据实验室，展示数据规模和 smoke 通过状态。

### 7.2 用户日常流程

1. 选择用户画像。
2. 输入兴趣或目的地。
3. 获取景点和美食推荐。
4. 规划路线。
5. 保存路线或收藏景点。
6. 游览后写日记并查看社区日记。

- 路线页使用全屏 split view。

## 9. 与当前前端的主要差异

当前 `web/` 前端更像课程验收控制台，新方案更像真实旅行产品。

需要调整：

- 从六个平铺 tab 改为四个主页面 + 数据实验室。
- 从文字密集面板改为图片卡片、玻璃浮层、地图主画布。
- 路线页成为核心体验，不再只是一个普通 tab。
- 推荐、日记、美食都使用统一卡片系统。
- 算法说明从长文本改为轻量 badge + 可展开详情。
- 移动端增加底部导航和路线抽屉。

需要保留：

- 纯静态前端。
- 读取当前 JSON 数据。
- Leaflet 本地文件。
- 离线底图失败兜底。
- smoke 验证脚本。

## 11. 风险与处理

| 风险 | 处理 |
| --- | --- |
| Stitch 图片多为外链，答辩可能断网 | 使用本地 SVG 或补充本地真实图片，外链只作为参考 |
| 玻璃拟态影响文字可读性 | 所有正文使用高对比 slate 色，图片上必须有渐变遮罩 |
| 前端算法和 C++ 算法不一致 | 推荐和多点路线优先统一权重与 TSP-DP 逻辑 |
| 页面太像旅游网站，弱化课程重点 | 每页保留 AlgorithmBadge 和数据证明面板 |
| 移动端地图和详情冲突 | 使用底部抽屉承载路线步骤 |

## 12. 最终效果目标

重写后的前端应达到：

- 第一眼像一个成熟旅行产品，而不是课程作业页面。
- 功能上完整覆盖课程 PPT 要求。
- 答辩时能自然讲出每个模块背后的数据结构和算法。
- 即使没有网络，也能加载本地数据和 Leaflet，展示核心流程。
- 前端风格和 Stitch 保持一致：轻盈、明亮、玻璃拟态、图片驱动、蓝橙绿旅行调性。
