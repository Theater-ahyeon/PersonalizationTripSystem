## 本轮已执行

1. 在探索页加入 `LSH 兴趣候选 + Top-K 最小堆` 算法提示。
2. 在 `web/app.js` 新增 `topK()`、`heapPush()`、`heapSink()`，替换目的地和美食推荐中的全量排序截断。
3. 新增 SimHash + LSH 索引函数：`buildSimilarityIndexes()`、`buildLshIndex()`、`getLshCandidates()`、`simhashSignature()`、`lshBandKeys()`。
4. 日记兴趣推荐接入 LSH 候选集，并在页面展示检索方式、候选数量和压缩证据。
5. 地图控件新增数据包提示：全国底图可以浏览，但路线/设施算法使用当前加载的本地道路图数据包。
6. 删除旧 `renderDataOverview()` 死代码，避免“验收台”页面概念残留。
7. 更新 `web/scripts/smoke.ps1`，自动检查 LSH、Top-K 堆、算法提示容器和验收台移除状态。
8. 新增区域数据包清单 `cpp/data/regions/manifest.json`，路线页可以看到“已激活/待接入/模板”的数据包状态。
9. 前端日记全文检索从 `includes()` 改为 `kmpContains()`，并在日记页显示结果平均 Huffman 压缩率。
10. 探索页新增目的地查询和排序控件，覆盖名称、类别、关键字查询，以及热度/评分/兴趣/综合推荐。
11. 设施页新增范围过滤，查询结果先 GeoHash 缩小候选，再按图上最短路径距离排序。
12. 日记页新增保存日记、图片/视频文件选择、浏览量 +1、当前用户评分、标题 HashMap 索引和前端 Huffman 压缩字节估算。
13. 美食页新增热度、评分、距离、综合排序，模糊查询覆盖餐厅名称、菜系和附近景点名。
14. 清洗 `cpp/data/spots.json`，删除 `????` 等无意义占位数据，保留颐和园路网绑定点，并扩展到 247 个真实景区、博物馆、古镇、自然地标和高校名称。
15. 补充 53 个北京高校真实坐标节点和本地 SVG 图标；这些节点用于地图展示、推荐和查询，暂不进入路线下拉和多点游览。
16. 新增 `tsinghua_campus` 校园数据包，包含 14 个校园节点、36 条有向边、8 个设施和 6 条餐饮数据。
17. 新增日记 JSON 导出入口，导出当前新增日记、浏览量和评分状态。
18. 将 AIGC 文案改为“模拟日记草稿/模拟分镜/待接入模型”，避免答辩误导。

## 仍需扩展的真实工程能力

当前系统可以在全国地图上浏览城市和底图，并且真正能做路线规划、设施图上距离排序、多点游览的道路图数据包已有颐和园和清华校园两个。要做到“全国都能使用这个系统”，下一阶段继续扩展区域数据包架构：

- `cpp/data/regions/{region_id}/spots.json`
- `cpp/data/regions/{region_id}/osm_nodes.json`
- `cpp/data/regions/{region_id}/osm_edges.json`
- `cpp/data/regions/{region_id}/roads.json`
- `cpp/data/regions/{region_id}/facilities.json`
- `cpp/data/regions/{region_id}/restaurants.json`

每个景区、校园或城市片区独立维护路网、设施、餐饮和景点数据。前端地图选择区域后加载对应数据包，算法层复用现有 Dijkstra、TSP-DP、GeoHash、LSH 和 Top-K。

本轮已经先落地 manifest 层，当前包含：

- `summer_palace`：已激活，可运行景区路线、设施和餐饮算法。
- `tsinghua_campus`：已激活，可运行学校内部路线、设施和餐饮算法。
- `beijing_city`：待接入，北京全域扩展占位。
- `shanghai_city`：待接入，跨城市扩展示例。
- `campus_template`：校园模板，用于后续学校内部道路、骑行、食堂、宿舍和室内导航扩展。

注意：不建议爬取高德地图瓦片或私有接口作为离线地图数据，容易触碰授权和稳定性问题。更稳妥的方案是使用 OpenStreetMap/Overpass 这类开放数据，或使用高德官方 API 并遵守其授权条款。
